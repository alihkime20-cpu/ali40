# GitHub Actions في SABACUN

يحتوي المستودع على سير عمل لجودة الكود والتحقق من جاهزية منصة الأدوات الرقمية. لم يعد المشروع يعتمد على مزامنة الأخبار أو خلاصات RSS أو تحديث ملفات أخبار دورياً.

## فحص المشروع عند Push

الملف `.github/workflows/ci.yml` يعمل عند كل Push إلى الفرع `main` وعند إنشاء Pull Request. ينفذ فحصاً لاكتشاف الأسرار المسربة، ثم يثبت الاعتماديات، ويفحص TypeScript، ويشغّل اختبارات Vitest، وينشئ نسخة الإنتاج عبر `pnpm build`. إذا فشل أي فحص، يفشل سير العمل ويجب إصلاح المشكلة قبل اعتبار التعديل صالحاً.

يستخدم هذا السير أقل صلاحية ممكنة: `contents: read`. ولا يحتاج إلى مفتاح مخصص؛ يستخدم `GITHUB_TOKEN` المدمج الذي تنشئه GitHub لكل تشغيل.

## التشغيل والمراجعة

يمكن مراجعة نتائج الفحص من تبويب **Actions** في المستودع، حيث يظهر كل تشغيل مرتبطاً بالـcommit أو Pull Request الذي سببه. يجب مراجعة سجل التشغيل بعد أي فشل، خصوصاً فشل TypeScript أو الاختبارات أو بناء الإنتاج.

لا تضع مفاتيح API أو كلمات المرور أو ملفات `.env` في المستودع. إذا احتاجت أداة مستقبلية إلى خدمة خارجية، تُضاف بياناتها من إعدادات **Repository secrets** ولا تُكتب داخل ملفات YAML أو الشيفرة المصدرية.

تعالج أدوات SABACUN النصوص والصور داخل المتصفح قدر الإمكان، ولا تعتمد على مهمة خلفية دورية لإنتاج محتوى منشور. لذلك تظل جودة المحتوى ومراجعة مقالات مركز المعرفة ضمن دورة تطوير واضحة، بدلاً من نشر بيانات آلية غير مراجعة.
