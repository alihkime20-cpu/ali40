# GitHub Actions في نبض العالم

يحتوي المستودع على سيرَي عمل مستقلين لإدارة جودة الكود ولقطة الأخبار العامة.

## فحص المشروع عند Push

الملف `.github/workflows/ci.yml` يعمل عند كل Push إلى الفرع `main` وعند إنشاء Pull Request. ينفذ فحصاً لاكتشاف الأسرار المسربة باستخدام Gitleaks، ثم يثبت الاعتماديات، ويفحص TypeScript، ويشغّل اختبارات Vitest، وينشئ نسخة الإنتاج عبر `pnpm build`. إذا فشل أي فحص، يفشل سير العمل ويجب إصلاح المشكلة قبل اعتبار التعديل صالحاً.

يستخدم هذا السير أقل صلاحية ممكنة: `contents: read`. ولا يحتاج إلى مفتاح مخصص؛ يستخدم `GITHUB_TOKEN` المدمج الذي تنشئه GitHub لكل تشغيل.

## تحديث الأخبار كل 30 دقيقة

الملف `.github/workflows/news-sync.yml` يعمل وفق الجدولة `*/30 * * * *`، ويمكن تشغيله يدوياً من تبويب Actions عبر زر **Run workflow**. يجلب السكربت `scripts/sync-news-to-github.ts` عناوين حديثة من أربع خلاصات RSS عامة، ثم يكتبها في `data/news-latest.json`. بعد ذلك ينشئ Commit ويرفعه إلى الفرع `main` فقط إذا تغيرت البيانات.

هذا المسار يحفظ **لقطة الأخبار العامة داخل GitHub** كما تم طلبه. لا يكتب مباشرة إلى قاعدة بيانات الموقع ولا يستبدل آلية Heartbeat الموجودة في الاستضافة؛ لذلك يبقى تحديث الأخبار داخل الموقع معتمداً على مسار الخادم والقاعدة الحاليين.

يستخدم هذا السير `contents: write` لأن GitHub Actions يحتاج إلى Commit وPush للقطعة المحدثة. لا توجد أسرار مخصصة مطلوبة، لكن يجب أن تبقى صلاحية `GITHUB_TOKEN` الافتراضية للكتابة متاحة للمستودع، ويُفضّل عدم توسيع الصلاحيات الأخرى.

## التشغيل والمراجعة

للتشغيل اليدوي، افتح تبويب **Actions**، اختر **Refresh public news snapshot**، ثم اضغط **Run workflow**. أما التشغيل الدوري فيبدأ تلقائياً من GitHub وفق الجدولة، مع ملاحظة أن تشغيلات الجدولة قد تتأخر قليلاً عند ضغط GitHub.

يجب مراجعة سجل التشغيل بعد أي فشل. لا تضع مفاتيح API أو كلمات المرور أو ملفات `.env` في المستودع. إذا احتاج مصدر RSS مستقبلاً إلى مصادقة، تُضاف بياناته من إعدادات **Repository secrets** ولا تُكتب داخل ملفات YAML أو السكربت.
